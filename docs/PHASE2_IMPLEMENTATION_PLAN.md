# Phase 2 implementation plan

**Date:** 2026-09-30  
**Status:** implementation freeze before confirmation execution

## Scope

Phase 2 implements the closed-loop evaluation infrastructure specified by `docs/EVAL_PROTOCOL_v2.md` without modifying frozen planner files.

### 2.1 Closed-loop simulator
`experiments/phase2_closed_loop.py` provides:
- robot state and trajectory;
- dynamic-obstacle evolution;
- noisy observations;
- constant-velocity Kalman estimation;
- replanning;
- physical collision and goal checks.

### 2.2 Logging
`experiments/phase2_logger.py` records every replan, planning time, planner success/failure, collision events, and run-level primary/secondary metrics.

### 2.3 Space-time A*
`experiments/phase2_planners.py::space_time_astar` uses `(row, col, t)` states and predicted dynamic-obstacle occupancy.

### 2.4 D* Lite + local planner
`experiments/phase2_planners.py::DStarLite` provides incremental grid replanning; `dwa_local_step` supplies the local dynamic-window-style motion selection on the same grid/world interface.

### 2.5 Scenario generator
`experiments/phase2_scenario_generator.py` generates 240 seed-controlled scenarios by default and supports >=200 scenarios spanning workspace size, static density, 1–8 dynamic obstacles, constant/curved/stop-go/random-walk motion, and four observation-noise levels.

### 2.6 Reproduction check
After adding Phase-2 implementation modules, the existing `experiments/verify_reproduction.py` is run as a provenance guard. It must remain unchanged and existing stored-run behaviour must still reproduce.

## Freeze boundary

This implementation plan and the Phase-2 module hashes are frozen before any confirmation results are inspected. The Phase-2 smoke test is an implementation test only; it is not confirmation evidence and is not used for parameter selection.

## Confirmation exclusion

No Phase-2 confirmation dataset is generated by the implementation step. Confirmation execution begins only after the code/parameter manifest and analysis plan are frozen.
